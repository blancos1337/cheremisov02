## 3. Теоретические сведения

### 3.1. Удалённые репозитории

Удалённый репозиторий — это версия проекта, размещённая на сервере. Он позволяет хранить изменения и обмениваться ими между участниками разработки.

Основные команды Git для работы с удалёнными репозиториями:

- `git remote -v` — просмотр подключённых удалённых репозиториев;
- `git remote add` — добавление удалённого репозитория;
- `git fetch` — получение информации об изменениях удалённого репозитория без автоматического объединения;
- `git pull` — получение изменений и их объединение с текущей веткой;
- `git push` — отправка локальных изменений на сервер.

### 3.2. Модель совместной разработки

Совместная разработка позволяет нескольким участникам работать над одним проектом, не мешая друг другу.

Типичный процесс включает следующие этапы:

1. Создание или получение копии репозитория.
2. Создание отдельной ветки для работы.
3. Внесение изменений в файлы проекта.
4. Создание коммитов.
5. Отправка ветки на удалённый сервер.
6. Создание Pull Request или Merge Request.
7. Проверка изменений с помощью Code Review.
8. Объединение изменений с основной веткой.

### 3.3. Синхронизация Fork с upstream

В модели разработки через Fork удалённый репозиторий `origin` обычно указывает на личную копию проекта, а `upstream` — на исходный репозиторий.

Для получения изменений из исходного проекта используются команды:

```bash
git remote add upstream git@gitlab.com:original-owner/original-repo.git
git fetch upstream
git checkout main
git merge upstream/main
```

В данной лабораторной работе отдельный Fork и remote `upstream` не создавались. Практическая часть выполнялась в существующем репозитории GitHub с использованием отдельной ветки и Pull Request.

## 6. Ответы на контрольные вопросы

**1. Что такое Fork?**

Fork — это независимая копия чужого репозитория в учётной записи пользователя. Она позволяет вносить изменения, не изменяя исходный проект напрямую.

**2. Чем отличаются команды fetch и pull?**

`git fetch` получает изменения из удалённого репозитория, но не объединяет их с текущей веткой. `git pull` получает изменения и выполняет их объединение с текущей веткой.

**3. Для чего нужен remote upstream?**

`upstream` обычно используется для обозначения исходного репозитория, из которого был создан Fork. Он позволяет получать обновления оригинального проекта.

**4. Что такое Merge Request или Pull Request?**

Это запрос на объединение изменений из одной ветки в другую. Он позволяет проверить изменения и обсудить их до включения в основную ветку.

**5. Какие этапы включает процесс Merge Request?**

Создание отдельной ветки, внесение изменений, создание коммитов, отправка ветки на сервер, открытие запроса на объединение, проверка кода и объединение изменений.

**6. Что такое Code Review?**

Code Review — это проверка программного кода другими разработчиками. Она помогает обнаружить ошибки, улучшить читаемость и повысить качество проекта.

**7. Как обновить Fork из исходного репозитория?**

Необходимо получить изменения из `upstream`, объединить их с основной веткой и отправить обновления в свой Fork:

```bash
git fetch upstream
git switch main
git merge upstream/main
git push origin main
```

**8. Что такое Protected Branches?**

Protected Branches — это защищённые ветки, для которых установлены специальные ограничения. Например, можно запретить удаление ветки и принудительную отправку изменений.

**9. Чем отличаются Merge commit, Squash и Rebase?**

- Merge commit объединяет ветки с созданием отдельного коммита слияния.
- Squash объединяет несколько коммитов в один.
- Rebase переносит коммиты на новую базу, изменяя историю ветки.

**10. Как добавить нескольких участников в проект?**

Для этого можно добавить сведения об участниках в файл `CONTRIBUTORS.md`, а при совместной работе предоставить им доступ к репозиторию через настройки проекта.
